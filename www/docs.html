NavPlace documentation

NavPlace turns one plain-text list of links into a launcher you open with a keystroke, a page, and a widget for any site. This page covers all of it: the goals, the desktop app, the format, the designs, the embed widget and how the code is laid out.

Goals

  • Primary: navigate to the right place in a couple of keystrokes, dozens of times a day.
  • Secondary: render the same file as widgets and web pages.

NavPlace is a starting point, not a destination. Every option starts on screen; a few letters narrow them; Enter opens the one left on top.

Approaches

  • Plain text is the source. A name and a url per line. No JSON, no YAML, no editor needed.
  • One parser. lib/parse.js reads the text in the desktop app and in every design, so a collection behaves the same everywhere.
  • A design is a folder. designs/<name>/index.html, switched by one line: % design: <name>.
  • The window never waits. In the desktop app, the hotkey shows the window first and reloads the links behind it.
  • No build step. Designs and lib/ are plain files, served as they are.

One source, three surfaces

SurfaceLinks come fromFor
Desktop app~/.navplace/README.mdDaily navigation: hotkey, a few letters, Enter.
Embed widgetThe data-links attribute of its script tagA page, or a part of one, on any site.
PlaygroundIts text, kept in this browserTrying the format and the designs, then copying the embed code or opening it in CodePen.

The Playground is the quickest way to try it: pick a design, edit the links, see the preview, then copy the embed code or open it in CodePen. It has three tabs over the same work: Basic is the text and the preview; Advanced colours the links and shows the JSON of the line the cursor is on, or under File of the whole file, editable both ways; Design edits the design's own files beside the preview. Under Advanced and Design, an errors panel names the line each error came from, and in orange each line that was skipped with a warning, which is underlined in the text with why after it. Ctrl+V with a picture on the clipboard, a screenshot or a copied image file, adds % picture image1: data:… on a new last line, its name selected to rename; on a link's line, the link takes @image1 too, in place of the picture it had. A copied file gives its own name, and a name already taken gets 2, 3, 4. Renaming a picture, on its % picture line or in a link's @name, renames it everywhere, and one Ctrl+Z takes back both; a link given another picture's name shows that picture instead. A failed load stays in the errors panel only while the text still has that picture. A picture over 100 KB as a data url is drawn smaller, as WebP, until it fits. Drag the lines between the panes to resize them; each tab keeps its sizes.

Desktop app

An Electron app that hosts one design full-window and feeds it your links. It has no interface of its own: what you see is the design. It is built as a Linux AppImage only.

Install

Download the AppImage from releases/latest.

chmod +x NavPlace-*.AppImage
./NavPlace-*.AppImage

First run

  • The app reads ~/.navplace/README.md. When the file is missing it writes a starter one: % design: github and eight links (ChatGPT, GitHub, Gmail, Google Calendar, Google Drive, MDN, Node.js, Electron).
  • % design: picks the folder under designs/. Absent, or not one of them: github.
  • The window is 1200 × 1000, centred, always on top, zoomed to 125%. Its title is the design's title and the app's version.
  • It hides when it loses focus and stays running, so the hotkey brings it back at once.
  • Links open in your default browser.

Global hotkey on GNOME

./NavPlace-*.AppImage --configure-gnome

Run it once, from the AppImage itself (it needs the APPIMAGE variable the AppImage runtime sets) with node on PATH. It:

  1. copies the launcher to ${XDG_CONFIG_HOME:-~/.config}/navplace/launcher.js;
  2. binds Ctrl+Shift+Alt+N to it through dconf;
  3. writes ${XDG_DATA_HOME:-~/.local/share}/applications/navplace.desktop, which starts the AppImage;
  4. prints the launcher path, the AppImage path and the node it found.

Only GNOME is wired up. The launcher is plain Node, so any hotkey tool can run it, but its cold start calls gtk-launch navplace, which needs that desktop entry. A build from source has its own script for the AppImage in src/desktop-electron/build/: src/desktop-electron/bin/configure-gnome.

Instant launch

  1. The hotkey runs launcher.js: Node built-ins only, no Electron, no AppImage to mount.
  2. It connects to ${XDG_CONFIG_HOME:-~/.config}/navplace/navplace.sock.
  3. The running app shows its window, focuses it and clears the search box.
  4. No socket: gtk-launch navplace starts the app once. From then on the hotkey only pings the socket.

A second start of the app shows the running window instead of opening another one.

The window never waits. Each press of the hotkey reloads the links in the background: the window shows what it already has and the design redraws when the new links arrive. At startup the app reads the file once before the window opens, because its % design: decides what to load. % include: urls always come after the window is up. Measured with an include url delayed by 3 seconds, under Xvfb: window up in 569 ms, the hotkey answered in 4 ms, the pulled links in 3597 ms. Details: docs/instant-launch.md.

Chrome on Wayland

With several workspaces, Chrome on Wayland can open a link in a window on another workspace. When Google Chrome handles http and https links, the app first focuses a Chrome window on the current workspace (else the most recently raised one), then opens the link. It needs the optional GNOME extension Window Calls; without it, or outside a Wayland session, links open as Chrome decides. Details: docs/wayland-chrome-window.md.

What a design can reach

The window cancels every request except these: app://favicon/, blob:, chrome://, chrome-devtools://, data:, devtools://, file://, private://. Remote fonts, scripts and images do not load in the desktop app.

  • app://favicon/<host>: the app fetches the icon once from Google's favicon service and keeps it in its user data folder.
  • private://<path>: a file under ~/.navplace/, nothing outside it. .svg is sent as image/svg+xml, anything else as image/png.

Format

A NavPlace document is plain text. One line is one thing; the first character of a line decides what. Leading spaces are ignored.

Legend

Anything else is skipped without a message.

Example

% design: showcase
% title: Vladimir Barbarosh

# GitHub | Work
node-helpers                                     https://vbarbarosh.github.io/node-helpers
vue-modal          #frontend                     https://vbarbarosh.github.io/vue-modal
Gmail              #mail #padding=1 @img/gm.png  https://mail.google.com/
                                                 https://www.linkedin.com/in/vbarbarosh/
  • % design: picks the design. % title: hands it free text.
  • # GitHub | Work puts the four links below it in two sections.
  • #frontend and #mail are tags. #padding=1 reaches the design as meta.padding.
  • @img/gm.png shows ~/.navplace/img/gm.png next to Gmail.
  • The last link has no label. It becomes www.linkedin.com/in/vbarbarosh/.

% key: value — directives

DirectiveEffect
% design: xA folder name under designs/. When absent: github in the desktop app, basic in the embed widget.
% title: xText for the design's title element.
% email: xText for the design's email element; when that element is a link, its href too.
% ns: a | bKeeps only the links that sit under a section named a or b.
% picture name: uNames a picture for @name: u is an https://, http:// or data:image/ url. Repeatable, one name per line.
% include: uDesktop app only. Pulls the document at url u and appends its links.
% other: xFree. A design can map any key to an element of its own.
  • A directive is valid anywhere in the file, not only at the top.
  • The value is required. % oops is skipped with a warning; the rest of the file still parses.
  • The same key twice: the last one wins (% include: adds up instead).
  • Keys keep their case. % Design: and % design: are two keys.

% include: — pulling other documents

Desktop app only. The embed widget and the designs on the web read the directive and do nothing with it.

% include: https://example.com/links.md #work #prefix=ACME

The url first, then optional decorations for every pulled link:

OptionEffect
#tagAdds a tag. Repeatable.
#prefix=xPuts x and a space in front of every pulled label.
#suffix=xPuts a space and x after every pulled label.
  • Values hold no spaces. Unknown options are ignored.
  • Repeatable: every line adds one source, in file order; pulled links land after the local ones.
  • The url must return the document as plain text over http:// or https://; any other url is skipped.
  • A pulled document gives links and sections only. Its own directives are dropped, so it cannot switch the design, apply % ns: or pull a third document.
  • The % ns: of the pulling document filters local and pulled links alike.
  • The prefix and the suffix are part of the label, so typing the prefix finds the pulled links.
  • The request carries no access token.
  • A url that fails is logged and skipped; the rest still loads. Each url gets 5 seconds.
  • No pull runs in front of the window: it opens on the local links and redraws when the pulled ones arrive.

# Section — sections

A section applies to every link line below it, until the next section. A blank line does not end it. Sections are metadata: no design in this repo draws them; % ns: filters on them, and a design can read item.namespaces.

# Work | Internal

One line, two names. Two heading lines in a row join into one, with a space between them: # Work then # Fun gives one section named Work Fun. To start a new section, put a link line or a blank line between them.

label url — links

The url ends the line. http://, https:// and file:// are recognised. Spaces between the label and the url are free: align the columns as you like.

The label is optional. Without one, NavPlace builds it from the url: the host, plus the path when the path is not /.

#tag and #key=value

Both live inside a link line, before or after the label, and both drop out of the label. Tags join the label in the search text. #key=value pairs do not; they reach the design as item.meta.key. Designs in this repo read padding, domain, description and category this way.

Names accept a..z, A..Z, 0..9, _ and -. A value runs to the next space or #.

@name — images

@name must stand right before the url, after a space, or open a line with no label. When the file names it with % picture name:, the link gets that url; anywhere in the file will do, the end too. Otherwise it points at a file under ~/.navplace/: the parser turns it into private://name, which only the desktop app serves. In the Playground, Ctrl+V with a picture on the clipboard writes the % picture line for you. Designs that show artwork use item.image_url and fall back to item.icon_url.

Kimi    @kimi   https://kimi.com/
Grafana @board  https://grafana.com/

% picture kimi: data:image/png;base64,iVBORw0KGgo…
% picture board: https://example.com/img/board.jpg
  • The desktop app shows data: pictures; it blocks every web url, https:// pictures too.
  • The same name twice: the last one wins. A value that is not one of the three kinds of url is skipped with a warning, and @name stays a file under ~/.navplace/.

What a link becomes

The % lines go into one meta object for the whole document; each link line becomes an object of items. A line that does not parse is skipped and named in warnings, {line, text, message}, which is there only when there are any. On the right, what lib/parse.js makes of the text on the left, run on this page as you read it:

links.txt
% design: showcase
% title: Jane Doe
% email: jane@example.com

# Work | Mail
Gmail #mail #padding=1 @gm.png https://gmail.com/
Почта #mail https://ya.ru/
parse(text)
FieldFrom
labelWhat is left of the line after the url, tags and image are removed.
hrefThe url.
icon_urlapp://favicon/<host> in the desktop app, /icon/<host> on navplace.com (its own icons, for its own pages only), https://icon.horse/icon/<host> elsewhere.
image_urlFrom @name: the url of % picture name: when the file has one, else private://<name>; null without @name.
tagsEvery #tag on the line.
metaEvery #key=value on the line.
search1Label and tags, lower case, Cyrillic transliterated to Latin.
search2The url, same treatment.
namespacesThe names of the section above the line.

Gotchas

  • The url must end the line. Text after it drops the whole line.
  • A line that starts with # is a section, never a link. Put tags after the label.
  • @name needs a space in front of it. @img.png https://… becomes the label.
  • Tag names are ASCII. #дев stays in the label as plain text.
  • A line with no url is skipped in silence. A broken % line throws.
  • There is no comment syntax: % starts a directive.

Filtering

Type a few letters and press Enter: the top match opens.

  • The list shows the links that match what you typed: matches in the label and tags (search1) first, then matches in the url (search2).
  • Matching runs on lower-case text, and what you type is used as typed: type in lower case.
  • Transliteration works one way: git finds an item labelled Гитхаб; Cyrillic typed in the box finds nothing.

Several links at once

Separate words with spaces. Each word is an expression of its own and picks its top match; Enter opens all of them. gh mail cal opens three links. The list shows the matches of the last word. A click on a link opens it together with the top matches of the words before the last.

Search expressions

InputMatches
gitContains git.
^gitStarts with git.
git$Ends with git.
!gitDoes not contain git.
git/apiContains both git and api.
gh mailTwo expressions. Enter opens the top match for each.

The operators combine inside one part: ^git/!api starts with git and does not contain api.

Designs

A design is a folder under designs/ with its own index.html; the parser gives it the links and the design decides how to draw them. Most folders also carry a links.txt, the sample the Playground loads; a few a theme.css.

KindDesigns
Launchers: a search box on top, a dense list below; best in the desktop appgithub (the desktop default), palette (a command palette for the hotkey), basic (the embed default), google-chrome, basic-for-internal2, basic-for-internal3-with-groups
Presentation: themed pages, content firstshowcase, cards (sections as categories), basic-for-portfolio, basic-for-kids, basic-for-kids2, basic-for-recipes

Writing a design

<script src="../../lib/navplace.js"></script>
<script>
    navplace({
        input: 'input[type=search]',
        update: function (items) {
            // draw items: the filtered list, best match first
        },
        meta: {title: '.title', email: 'a.email'},
    });
</script>
  • input: the search box, a selector or an element. Typing anywhere on the page focuses it.
  • update(items): called with the filtered list whenever it changes. Each item has the fields in What a link becomes.
  • meta: maps directive keys to elements; the runtime writes the value into each element's text.
  • navigate(item): optional; replaces what Enter does for each selected link.
  • Clicks call navplace.navigate(item, event), so a click opens the selection of several words too.
  • Fonts, scripts and images ship inside the folder or inline: the desktop app blocks remote requests.

The same file runs in the desktop app (links from window.ElectronApp), inside the embed widget and in the Playground (links by postMessage). The full guide for writing one: specs/DESIGN.ai.md.

To work on one, open the Playground's Design tab: the % design: line opens the design's folder there, a tab per file, and every edit redraws the preview. The edits stay in the browser until Load brings a design's files back; copy them into designs/<name>/ to keep them.

Embed widget

One script tag puts a collection on any page.

<div style="position: fixed; inset: 0;">
    <script src="https://navplace.com/lib/embed.js" data-links="
% design: showcase
% title: My links

# Work
GitHub  https://github.com/
Gmail   https://mail.google.com/
"></script>
</div>

The script puts an iframe right after itself, 100% wide and tall: give its parent the size the widget should have.

AttributeEffect
data-linksThe collection's text. Required.
data-designOverrides % design:. Default basic.
data-srcA url to load in the iframe instead of the design's page.
srcThe design is found next to it: <folder of embed.js>/../designs/<design>/index.html.

How it talks to the design

MessageDirectionWhen
{type: 'navplace:ready'}design → pageThe design's runtime has loaded.
{type: 'navplace:items-text', text}page → designThe answer to ready: the data-links text.
{type: 'navplace:focus'}page → designEvery key pressed on the host page; it focuses the design's search box.

Links open in the top window. The widget shows only its own data-links: % include: does nothing here.

Libraries

The shared code in lib/: plain files with no build step, loaded by the desktop app, the designs and the site.

FileRole
parse.jsThe parser: text in, {meta, items} out. A Node module and a browser global. Its options {prefix, suffix, tags, ns} serve % include:.
filter1_from_spec.jsCompiles one search expression (^, $, !, /) into a test; a copy from node-helpers.
navplace.jsThe runtime every design loads: the search box, filtering, the selection, Enter and clicks, the embed messages, and the items from window.ElectronApp in the desktop app. It loads the two files above from its own folder.
embed.jsThe embed widget.
parse.test.jsThe parser's tests (mocha, npm test).
parse.cli.jsParses a sample and prints the result.

In the desktop app, window.ElectronApp (from src/desktop-electron/renderer.js) gives a design api_items_all(), the collection now, and api_items_changed(callback), called with each new one; it returns a function that stops the calls. api_ping() answers pong <time>.

The desktop app

  • main.js: the window, loading ~/.navplace/README.md and its includes, the socket the launcher pings, the single-instance lock, the private:// and app:// protocols, the network gate.
  • launcher.js: the hotkey side; Node built-ins only.
  • renderer.js: the preload that gives designs window.ElectronApp.
  • helpers/: resolve_includes and parse_include_spec for % include:, configure_gnome, focus_chrome_window, wait_for_socket_connections.

The site

  • bin/build-www puts the site together in build/www/: www/, lib/ without the tests and the CLI, designs/ without the drafts, and designs/index.json, the Playground's list of designs with the files of each.

FAQ

Which platforms does the desktop app run on?

Linux, as an AppImage. The global hotkey is set up for GNOME only.

Where are my links?

Desktop app: ~/.navplace/README.md. Embed widget: in its data-links. Playground: in this browser. There is no server: % include: pulls links from any url.

Can the desktop app show several collections?

It reads one source. % include: pulls other documents into it.

Why does Git find nothing?

The links' text is lower case and what you type is matched as typed: type git.

Why does my design look different in the desktop app?

The desktop app blocks remote fonts, scripts and images. Ship them inside the design's folder or inline them.

Does the embed widget follow changes to my links?

No. It shows the text in its data-links.

Is it open source?

Yes, MIT: LICENSE.
