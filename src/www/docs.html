NavPlace docs

NavPlace opens the sites you use every day: press a hotkey, type a few letters, hit Enter. Your links live in one text file. This page gets you started and shows how to write that file.

Get started

NavPlace is a desktop app for Linux: one AppImage file, nothing to install.

Install

Download the AppImage from the latest release, then:

chmod +x NavPlace-*.AppImage
./NavPlace-*.AppImage

The window opens with eight links to start from. They are in ~/.navplace/README.md, which the app has just written for you.

Add the hotkey

On GNOME, click the gear in the window, then GNOME setup, Set up. From then on Ctrl+Shift+Alt+N shows the window, and NavPlace starts when you log in. The setup needs node on your PATH.

The same from a terminal:

./NavPlace-*.AppImage --configure-gnome

Day to day

  • Press the hotkey: the window is there at once.
  • Type a few letters and press Enter: the link opens in your browser, and the window hides.
  • The window also hides when you click away from it. Closing it quits the app.
  • The gear opens the settings: your links in an editor, the design, the hotkey, start at login, zoom, and a check for updates.
  • An update is a new AppImage. Run it: it takes the old one's place.

Your links file

Your links are plain text in ~/.navplace/README.md. One line is one link: a name, then its address. Change it in any editor, or in the app's settings; the app reads it again every time you press the hotkey.

An example

% design: showcase
% title: My links

# Work
GitHub                https://github.com/
Gmail     #mail       https://mail.google.com/
Calendar  @cal.png    https://calendar.google.com/

# Reading
https://news.ycombinator.com/
  • GitHub https://github.com/ is a link: its name, then its address. The spaces between them are free, so the columns can line up.
  • # Work is a heading for the links under it.
  • #mail is a tag: typing mail finds the link.
  • @cal.png is a picture for the link.
  • A % line is a setting for the whole file.
  • The last link has no name. It is called by its address, news.ycombinator.com.

One line, part by part

Settings

LineWhat it does
% design: cardsPicks the look, one of the designs.
% title: My linksA title, in the designs that show one. % subtitle: and % email: work the same way.
% ns: WorkShows only the links under that heading. For two headings: % ns: Work | Home.
% picture cal: https://…Names a picture; a link takes it with @cal.
% include: https://…Adds the links of another file. Desktop app only.

A setting can stand anywhere in the file. Written twice, the last one wins; % include: lines add up.

Pictures

A design with tiles shows a link's picture when it has one, and the site's icon when it has not.

Kimi     @kimi   https://kimi.com/
Grafana  @board  https://grafana.com/

% picture kimi: data:image/png;base64,iVBORw0KGgo…
% picture board: https://example.com/img/board.jpg
  • @name stands right before the address.
  • With no % picture line of that name, it is a file of yours: @img/gm.png is ~/.navplace/img/gm.png.
  • % picture background: is the photo behind the links, in the designs that have one.
  • In the Playground, Ctrl+V with a picture on the clipboard writes the % picture line for you.

Links from another file

The desktop app can add the links of a file on the web, a list your team keeps for one:

% include: https://example.com/links.md #work #prefix=ACME
OptionWhat it does
#tagAdds a tag to every link of that file.
#prefix=xPuts x before every name.
#suffix=xPuts x after every name.
  • The window never waits for it: your own links show first, the others a moment later.
  • When the address does not answer, the last copy that did stands in.
  • The other file gives links and headings only: it cannot change your design or your settings.

Easy to trip on

  • The address ends the line. Text after it drops the whole line.
  • A line that starts with # is a heading, never a link. Put tags after the name.
  • @name needs a space in front of it.
  • Tag names are Latin letters, digits, _ and -.
  • A line with no address is skipped.
  • There are no comments: % starts a setting.

Every rule of the format, with its edge cases, is in the reference.

Finding a link

Type a few letters and press Enter: the top match opens.

  • Names and tags are looked at first, addresses after.
  • Capital letters do not matter.
  • Cyrillic and Latin letters find each other: git and гит both find Гитхаб.
  • ↑ and ↓ pick another match.

Several at once

Words with spaces between them each pick their own top match, and Enter opens them all: gh mail cal opens three links.

Narrower searches

You typeIt finds
gitWhat contains git.
^gitWhat starts with git.
git$What ends with git.
!gitWhat does not contain git.
git/apiWhat contains both git and api.

They combine: ^git/!api starts with git and has no api in it.

Designs

A design is the look of your links, and one line picks it: % design: cards. Seven come with NavPlace. A click opens one in the Playground.

  • github
  • palette
  • classic
  • google-chrome
  • showcase
  • cards
  • kids

The first four are launchers: a search box and a dense list, at their best in the desktop app. The other three are pages, with the content first. With no % design: line, the desktop app shows github and a widget on a page classic.

Writing your own

A design is a folder with one index.html. It loads NavPlace's script, says where its search box is, and draws the links it is given:

<script src="/lib/navplace.js"></script>
<script>
navplace({
    input: 'input[type=search]',
    update: function (items, {current}) {
        // draw items: the links that match, best first;
        // items[current] is the one Enter opens
    },
});
</script>

Try it in the Playground's Design code tab: every edit redraws the preview. The design guide has every call and every rule.

On a web page

One script tag puts your links on any page:

<div style="position: fixed; inset: 0;">
    <script src="https://navplace.com/lib/embed.js" data-links="
        % design: showcase
        % title: My links

        # Work
        GitHub  https://github.com/
        Gmail   https://mail.google.com/
    "></script>
</div>

The widget fills the element around it: give that element the size you want.

AttributeWhat it does
data-linksYour links, written as in the file.
data-designThe design, in place of a % design: line. classic when neither is there.

The widget shows the links in its tag and nothing else: % include: does nothing there. A link opens in the page's own tab.

Playground

The Playground is the quickest way to try all of this: links on the left, the result on the right. When it looks right, copy the embed code or open it in CodePen.

TabWhat it is
BasicThe text and the preview.
AdvancedThe text in colour, with the data of the line you are on.
Design codeThe design's own files, to edit beside the preview.
  • Ctrl+V with a picture on the clipboard puts it into the text, made small enough to keep there.
  • Shrink pictures does the same for the pictures already in the text.
  • A line that is skipped gets underlined, with the reason after it.
  • Your text stays in this browser. A link to playground.html?design=cards opens the Playground with that design picked.

FAQ

Which systems does the desktop app run on?

Linux, as an AppImage. The hotkey is set up for GNOME only.

Where are my links?

In the desktop app: ~/.navplace/README.md. In a widget: in its tag. In the Playground: in this browser. There is no server and no account.

Can the desktop app show several files?

It reads one, and % include: adds others to it.

Why does my design look different in the desktop app?

The app loads nothing from the web for a design: no fonts, no scripts, no images. Put them into the design's folder.

Does a widget follow changes to my links?

No. It shows the text in its tag.

Why does a link open in a Chrome window on another workspace?

Chrome on Wayland does that. With the GNOME extension Window Calls installed, NavPlace opens the link in a Chrome window on the workspace you are on: how it works.

Is it open source?

Yes, MIT: LICENSE.

Goals

  • First: get to the right place in a couple of keystrokes, dozens of times a day.
  • Second: show the same file as a page or a widget.

How it gets there:

  • Plain text is the source. A name and an address on a line. No JSON, no YAML, no special editor.
  • One parser. The app and every design read the text with the same code, so a file behaves the same everywhere.
  • A design is a folder, switched by one line.
  • The window never waits. The hotkey shows it first and reads the links behind it.
  • No build step. The designs and the shared code are plain files, served as they are.

How it's built

FolderHolds
lib/The shared code: the parser, the search, the script every design loads.
designs/One folder per design.
src/desktop-electron/The desktop app.
src/www/This site: the home page, the Playground, these docs.
src/cloudflare/The Worker that serves the site and the links' icons.
docs/The notes in the repository, the full reference among them.
bin/The scripts below.

Every rule and every edge case, the desktop app's inner workings and the shared code file by file are in the reference.
